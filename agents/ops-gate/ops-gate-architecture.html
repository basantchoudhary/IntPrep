Architecture

How every check is verified

Nothing is silently skipped — every check declares how it is proven

Every check is categorised by how it is verified  —  nothing is silently skipped

AAuto-verified
Machine reads it. Rule decides. No human.
  • Test suite passing, coverage ≥ 80%
  • DQ pass rate, recon variance
  • Alerts on 100% of failure points
  • Zero secrets, zero config drift
  • Rollback executed in a sandbox
BAuto-assembled
Agent extracts & summarises. Ops judges.
  • Is the SLO realistic for this design?
  • Failure modes in the topology but missing from the docs
  • Runbook completeness
  • Fit against the reference architecture
CAttested
Cannot be automated. Named person signs, dated.
  • GxP impact assessment
  • DPIA / privacy approval
  • Business acceptance
  • Production owner & on-call rota
  • Vendor / contractual dependency
DWaived
Explicitly not applicable — never blank.
  • Requires a reason and an approver
  • Carries an expiry date
  • Appears in the evidence bundle
  • Re-tested at the next release
The maturity measure is the share of checks in Category A — and it rises release on release. Manual work isn’t eliminated by pretending it’s automated. It is declared, owned, dated and made visible.
