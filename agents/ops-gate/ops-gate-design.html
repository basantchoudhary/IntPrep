Ops Gate Agent — Detailed Design

Deterministic gate · agentic comprehension · human signature

Flow

Project teamself-checks against the same spec
→
Collect evidencetests, DQ, IaC, cost, telemetry
→
Agent comprehendsdocs & estate → structured claims
→
Gate evaluatesdeterministic verdict
→
Human signspass / conditional / fail
→
Day-2 monitorschecks deploy as live monitors

Layers

1Check spec (as code)Versioned, declarative YAML. One source of truth for self-check, gate and day-2 monitoring. This is the reusable artefact.
2Evidence collectorsDeterministic adapters onto the platform's horizontal services — testing, data expectations, observability, FinOps, catalog, repo & IaC scan.
3Comprehension layer (LLM)Reads sprawling handover docs and undocumented estate; emits structured claims mapped to check IDs; explains failures; drafts the missing artefact.
4Gate engineEvaluates evidence against thresholds. Pure rules — replayable, explainable, identical every run. No model involvement in the verdict.
5Evidence bundle & sign-offImmutable, versioned, audit-ready. A named person signs. The bundle is the compliance record.
6Day-2 handoverChecks marked day2: deploy as monitors; failures route to the Self-Healing agent with the gate's own remediation.

Deterministic — the default

The checklist. Thresholds. Evaluation. The verdict. Evidence integrity and the audit trail. Anything a regulator may ask us to reproduce in three years.

Agentic — by exception

Comprehension of unstructured docs and unfamiliar estates. Explaining why a check failed. Proposing remediation. Drafting the missing runbook, alert or DQ rule.

Human — always

The production-acceptance signature. Category C attestations. Every waiver. The model never approves a deployment — it assembles the evidence a person signs.

Composed from the base agents
  • Test Framework Generator — supplies functional evidence; drafts the tests when coverage fails
  • Data Expectation Services — DQ, profiling, reconciliation evidence; proposes rules where none exist
  • Sandbox Creator — proves rollback and clean IaC deploy by executing them in isolation
  • Reverse Engineer IaC — recovers the real topology when documentation is stale, and detects drift
Packaged as a skill — so it travels
  • Spec + collectors + gate ship as one installable unit
  • A team adopts the bar without adopting our tooling opinions
  • Domain overlays extend the base spec; the core stays versioned centrally
  • Spec version is recorded in every evidence bundle — the bar is auditable over time
The handover stops being a document review and becomes a build step. Same spec, three moments: the team's self-check, the gate, and day-2 monitoring.

The checklist as code

One spec · three uses · versioned 
# auto-verified, with a base agent on failure
- id: FUN-03
  title: Data quality expectations passing
  category: A
  severity: blocker
  evidence:
    source: data-expectation-service
    query: expectations.{defined,pass_rate}
  rule: defined > 0 and pass_rate >= 99.5
  on_fail:
    agent: data-expectation-agent
  day2:
    schedule: every_run
    alert: dq-breach

# agent assembles — a human still decides
- id: NFR-05
  category: B
  evidence:
    source: agent
    prompt: >
      Extract every declared failure mode from the
      design pack. Cross-check against the deployed
      topology. List what the topology has and the
      documentation does not.
# manual — declared, owned, dated, expiring
- id: REG-01
  title: GxP impact assessment complete
  category: C
  severity: blocker
  attestation:
    role: quality-lead
    requires: [signature, date, document_link]
    expires_after_days: 365

# the verdict — pure rules, no model
verdict:
  fail:        any(blocker and status != pass)
  conditional: any(major   and status != pass)
  pass:        all(status == pass)
  signature:   required
Why as code
  • Reviewable, diffable, versioned — the bar itself has a change history
  • The team runs it locally; the gate runs the same file
  • Domains extend it by overlay without forking the core
  • The spec version is stamped into every evidence bundle
Backup 3

What stays manual, and what gets deployed

"Is anything still manual?" — yes, deliberately
Deliberately not automated
  • The production-acceptance signature. A model does not approve regulated change. It never will in this design.
  • Regulatory attestations — GxP, DPIA. A qualified person's judgement, recorded with identity and date.
  • Business acceptance. Fitness for purpose is not a technical property.
  • Category B judgements. The agent assembles the evidence and states the risk; Ops decides whether to accept it.
Automated end to end
  • Evidence collection across all six platform services
  • Evaluation, verdict computation and the evidence bundle
  • Extraction of claims from unstructured handover documents
  • Drafting of missing tests, DQ rules, alert rules and runbook sections
  • Deployment of passing checks as day-2 monitors
Waiver policy — how "not applicable" stays honest
  • A waiver requires a stated reason, a named approver and an expiry date
  • It is visible in the evidence bundle, not hidden in a config
  • It is re-tested at the next release — waivers do not accumulate silently
  • Waiver rate per domain is reported; a rising rate is a signal about the bar, not the projects
Failure modes of the gate itself
  • Evidence source unavailable → check fails closed, never passes by absence
  • Agent extraction is wrong → it only ever proposes; a deterministic rule or a human confirms
  • Gaming the thresholds → coverage and DQ are sampled independently by Ops post-handover
  • Spec rot → spec is versioned and owned; every bundle records the version it was judged against
Automating the assessment does not mean automating the accountability.

Rollout
  • 1 · Codify — turn today's handover document into the versioned spec, as-is. No new bar yet.
  • 2 · Shadow — run it alongside the existing manual review; compare verdicts to calibrate.
  • 3 · Shift left — publish the self-check so teams run it during build, not at handover.
  • 4 · Enforce — the gate becomes the route to production; waivers by exception.
  • 5 · Extend — domain overlays; day-2 monitors from the same spec.
Why it becomes the reused pattern
  • It ships as a skill — adoptable without adopting our stack
  • It starts as their checklist codified, so adoption is not a negotiation
  • Security and enterprise architecture get their controls enforced automatically — they become sponsors, not blockers
  • The same spec powers Ops Self-Monitoring and feeds Self-Healing — one artefact, three capabilities
One spec. Codified once, enforced everywhere, and it keeps working after go-live.
