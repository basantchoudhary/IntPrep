Base Agent

Test Framework Generator — Design

agents/test_framework/ · report the gap, then close it
The problem it removes

Coverage arrives at the gate as a number in a slide. Nobody can see which modules have no test at all, so the number is an average hiding a hole. And when the gate does find the hole, it hands the work straight back to a team that is already at go-live — which is how assurance earns its reputation as a tax rather than a service.

The promise

Read the harness output as evidence, name the modules with no test file, and — where coverage falls short — write the scaffold back out as a reviewable proposal. The gate stops being a list of complaints and becomes the thing that does some of the work. Absent results are not treated as a pass.

Deterministic — including the generation

Parsing results is arithmetic. So is the scaffold: the shape of a test file is knowable, so it is a template, not a prompt. This is the whole thesis in one function — do not reach for a model to produce something a format string produces identically every time.

Agentic — the assertions

A model is worth involving only in deciding what the assertions should be about for a given module. That is deliberately left as the open slot, and it is a category B judgement — proposed, never auto-accepted.

Human — completing the test

Every generated test is a skip with a TODO. It cannot go green on its own. The engineer writes the assertion; the agent removed only the blank-page problem.

A gate that only reports gaps moves work onto the project team. This one hands back the artefact. And the artefact it hands back is honest: a skipped test is visibly incomplete.

The generated scaffold

"""Generated scaffold for `ingest`.
Assertions are the author's to complete."""

import pytest
from src import ingest


def test_ingest_happy_path():
    pytest.skip("TODO: assert the expected output")

def test_ingest_rejects_invalid_input():
    pytest.skip("TODO: assert the failure mode is raised,
                 not swallowed")

def test_ingest_is_idempotent():
    pytest.skip("TODO: assert running twice produces
                 the same result")
Why three tests, and why these three

The template encodes what an Ops team actually needs to know about a data module before accepting it: does it work, does it fail loudly rather than silently, and can it be safely re-run. That third one is the reason most data incidents become two incidents.

So the scaffold is not a neutral stub — it is the readiness bar expressed as test names. A team that fills in only the happy path has visibly not finished, and the file says so.

Failure modes of the agent itself
  • Results are self-reported. The harness output is produced by the project's own pipeline. The gate trusts it as a stated fact, which is why coverage is sampled independently by Ops post-handover — the mitigation is organisational, not technical, and worth saying so.
  • Accepting the scaffold silences the gap detector. Once tests/test_ingest.py exists, untested_modules goes quiet even though every test skips. Coverage percentage — not file presence — is what FUN-02 actually gates on, which is why the rule is written against coverage.
  • Name-based matching. Modules are paired to tests by filename stem, not by import graph. Cheap, transparent, and wrong for unconventional layouts — a deliberate trade, replaceable without touching the interface.
  • No results file → available: false → ERROR. Never a pass.
Reuse beyond Ops Gate
  • Ops Self-Healing — the regression suite is what makes a remediation safe to apply. A fix that passes the same tests the gate ran is a fix; one that does not is a rollback.
  • Spark / Databricks Modernization — generate the safety net before refactoring. The tests are what let a modernization be reviewed as equivalent rather than trusted as equivalent.
  • Project scaffolding, day one — the same templates run at project start, so the readiness bar is visible on the first commit rather than at handover.
The scaffold is deterministic. The assertion is a judgement. The agent does exactly one of those. Generated tests skip by default — remediation must never manufacture assurance.
