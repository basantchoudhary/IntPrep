Base Agent

Reverse Engineer IaC — Design

agents/reverse_engineer_iac/ · the estate as deployed, not as described
The problem it removes

A handover pack describes the system as designed. The estate has drifted since — resources added by hand during go-live pressure, parameters changed and never back-ported. The documented failure modes are the ones somebody remembered to write down, which is never the same set as the ones the topology actually implies. Ops inherits a system it cannot see.

The promise

Recover the topology from deployed state, diff it against what was declared, and derive the failure register from the topology itself. That last step lets the gate ask a question a document review structurally cannot: which failure points exist in the deployed system but appear nowhere in the handover pack?

Deterministic — the derivation

Recovery, the diff and the failure-point derivation are all set arithmetic over a state file. The list of gaps is a fact, reproducible on demand — which is exactly why it can be put in front of a project team without an argument about whether the tool is being unfair.

Agentic — reading the pack

The one genuinely unstructured input is the handover documentation itself: extracting which failure modes a prose design document claims to cover. That extraction is a proposal fed into the comparison — it is never the verdict.

Human — the acceptability call

NFR-05 is category B on purpose. That four resources are undocumented is a fact. Whether that is acceptable for this system, on this risk profile, is a judgement — so the agent assembles and Ops decides.

A document review can only find what the document mentions. This agent compares the pack against the estate. It is the difference between reviewing a description and inspecting the thing.

Why this table is the whole idea

Failure-mode analysis is normally a workshop whose output depends on who attended. Encoding kind → modes makes the baseline analysis a property of the architecture rather than of the meeting. The workshop still happens — it now starts from a complete list instead of producing an incomplete one.

What Ops reads on the gate output

REVW [B] NFR-05 — 4 failure point(s) in the deployed topology are absent from the handover pack: curate_job, orders_stream, landing_store, fx_rates_api

Four named resources, each with the modes it introduces. That is a conversation with the project team that takes ten minutes and starts from evidence — not a three-hour review that ends in "looks fine".

Failure modes of the agent itself
  • An unrecognised resource kind contributes no failure points — a silent under-count, the most dangerous kind of gap in this agent. Partly covered by CFG-01, which flags any resource deployed but not declared, whatever its kind. Extending the map is a one-line change and should be a standing review item.
  • Documented-list matching is by lower-cased name. A pack that says "the curation job" rather than curate_job reads as undocumented. Category B exists precisely so a human resolves that rather than the gate blocking on it.
  • Deployed state is a snapshot. Drift found is drift at the moment of capture; the daily day-2 monitor is what turns a snapshot into a control.
  • State unreachable → available: false → ERROR. An estate that cannot be inspected does not pass a configuration check.
Reuse beyond Ops Gate
  • Ops Self-Monitoring — the daily drift check is this agent on a schedule. No new capability was built for it.
  • Ops Self-Healing — the recovered topology is the map a diagnosis walks. You cannot remediate a system you have not modelled, and this is where the model comes from.
  • Spark / Databricks Modernization — the common case is a legacy estate with no usable IaC at all. Recovery comes first; the modernization plan is written against the recovered topology.
  • Any inherited system — acquisitions, vendor handovers, a team that left. This is the agent that answers "what have we actually got?"
Derive the failure register from the architecture, and completeness stops depending on who was in the room. The workshop still happens — it just starts from a complete list.
